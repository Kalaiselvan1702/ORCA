## 2. Available Modalities & Schemas

The dataset incorporates all three fundamental observability signals generated by distributed microservice topologies:

### A. Metrics Modality
- **Format:** Parquet / JSON time series (`metrics.parquet`)
- **Granularity:** 1-second sampling interval across 1,441 timesteps (~24 minutes per incident).
- **Features:** System resource and operational metrics across services:
  - CPU usage (`<service>_cpu`)
  - Memory consumption (`<service>_mem`)
  - Network throughput receive & transmit (`<service>_network_receive`, `<service>_network_transmit`)
  - Disk operations / latency
- **Dimensionality:** 72 continuous metric series per timestep for Online Boutique (`RE2-OB`); 340+ for Train Ticket (`RE2-TT`).

### B. Logs Modality
- **Format:** Parquet / CSV (`logs.parquet`)
- **Fields:**
  - `timestamp`: Unix second timestamp aligned with metrics.
  - `container_name`: The microservice emitting the log event (e.g., `checkoutservice`, `cartservice`, `currencyservice`, `frontend`).
  - `message`: Raw text of the log message and error traces.
- **Volume:** ~100,000 to 200,000 log events per incident.

### C. Traces Modality (Distributed Call Graph)
- **Format:** Parquet / CSV (`traces.parquet`)
- **Fields:**
  - `time`: Timestamp (HH:MM or Unix)
  - `traceID`: Unique trace identifier linking distributed sub-requests.
  - `spanID`: Unique span identifier.
  - `parentSpanID`: Calling span identifier (defines directed service-call topology).
  - `serviceName`: Initiating microservice.
  - `methodName` / `operationName`: HTTP / gRPC endpoint invoked.
  - `duration`: Call latency in milliseconds / microseconds.
  - `statusCode`: HTTP / gRPC status code (e.g., 0 for OK, non-zero for errors).
- **Volume:** ~200,000 to 400,000 trace spans per incident.

## 3. Ground Truth Labels & Incident Structure

Each incident in RCAEval is a controlled, reproducible fault-injection scenario with exact annotations indexed in `cases.parquet`:

- **Incident Duration:** 1,441 seconds (~24 minutes).
- **Normal Window:** First 720 seconds (Normal operation, label = `0`).
- **Fault Injection Timestamp (`inject_time`):** Unix timestamp marking exact start of the anomaly.
- **Faulty Window:** Final 721 seconds (Anomalous operation, label = `1`).
- **Ground Truth Root Cause Service (`root_cause_service`):** The verified microservice where the fault was injected (e.g., `checkoutservice`, `cartservice`, `recommendationservice`, `emailservice`, `paymentservice`, `productcatalogservice`, `shippingservice`, `frontend`).
- **Fault Categories (`fault`):**
  - `cpu`: CPU exhaustion / starvation.
  - `mem`: Memory leak / resource saturation.
  - `disk`: Disk I/O bottleneck / read-write delay.
  - `delay`: Network latency injection on service RPC interfaces.
  - `loss`: Network packet loss.
  - `socket`: Socket connection exhaustion.

## 4. Train / Validation / Test Splitting & Leakage Prevention

1. **Incident-Aware & Time-Aware Splitting:**
   - Splits are executed by grouping full incidents (cases), ensuring that time windows and traces from the same incident run never appear across both train and test splits (preventing temporal autocorrelation leakage).
   - In dev mode: 10 representative incidents spanning different fault categories and root causes are preprocessed into windowed multimodal sequences.
   - Standard split: 70% Train, 15% Validation, 15% Test.
2. **Scaler Leakage Prevention:**
   - Numerical metric scalers (StandardScaler / RobustScaler) and log vocabulary encoders are fitted strictly on the Training set and then applied transform-only on Validation and Test sets.
3. **Graph Topology Leakage Prevention:**
   - The microservice dependency graph is constructed from service discovery and upstream/downstream call graph relationships without using future ground truth or test traces.

---

## 5. Dataset Preprocessing Pipeline

1. **Windowing & Alignment:**
   - Observability signals are aggregated into uniform non-overlapping or rolling time windows (default `window_size = 10` seconds).
   - Metrics: Aggregate mean, std, min, max, slope over window.
   - Logs: Aggregate event counts, error counts, TF-IDF / sequence embeddings per window per service.
   - Traces: Aggregate span latencies, error span ratios, and adjacency call counts per window.
2. **Missing Value Imputation:**
   - Forward-fill followed by zero-fill for inactive service intervals.
3. **Graph Adjacency:**
   - Static/Dynamic adjacency matrix $A \in \mathbb{R}^{N \times N}$ representing inter-service RPC invocations between the $N$ microservices.

---

## 6. Known Limitations

- Real-world distributed systems have non-deterministic network jitter; simulated fault injection isolates specific microservice faults cleanly.
- While the full dataset spans 735 cases across 3 systems (3.4GB Parquet / ~38GB uncompressed), development and local benchmarking runs operate on curated subsets (`RE2-OB` cases) to respect student development environment compute and memory limits.
